## 1. このアプリでできること

画面は **3つ** あります。

| 画面 | だれが見る？ | できること |
| --- | --- | --- |
| **参加者画面** `/` | 会場の人（スマホ） | 「質問する」「感想を書く」を匿名で送る / みんなの投稿を見る / 投稿に絵文字👀💡🙌などでリアクション / いま答えている質問に「私も聞きたい👍」「共感❤️」を押す |
| **スクリーン画面** `/screen` | プロジェクターに映す | 新しい投稿が **右から左へ流れる**（質問＝青い帯、感想＝白い文字）/ 上に「いま回答中」の質問と 👍❤️ の数が出る |
| **講演者画面** `/speaker` | 話す人 | 質問が **リアクションの多い順** に並ぶ / 「回答する」ボタンで、その質問を「いま回答中」にする / 「回答済みにする」/ 感想は横に新しい順で並ぶ |

### 最低限ここまで作れば合格ライン（MVP）
「全部は無理かも…」となったら、まず ✅ を完成させます。⭐ は余裕があれば。

- ✅ 参加者が質問・感想を投稿できる（空はダメ、120文字まで）
- ✅ 投稿の一覧が見られ、**数秒ごとに自動で新しいものが増える**
- ✅ スクリーンに新しい投稿が流れる
- ✅ 講演者が「回答する」を押すと、参加者画面とスクリーンに「いま回答中」が出る
- ✅ 「私も聞きたい」「共感」を押せて、数が増える
- ⭐ 絵文字リアクション（8種類）
- ⭐ 講演者画面でリアクション順に並ぶ
- ⭐ 一覧／質問／感想 のタブ切り替え
- ⭐ 👍❤️ がスクリーンでふわっと浮かぶ演出

## 2. 使う道具（技術）と、使う理由

課題のルール: **HTML / Tailwind（CSSファイルは書かない）/ JavaScript / PHP / Laravel** を、カリキュラム w07 までの範囲で使う。
範囲の外のものを使うときは **「なぜ使ったか」を説明できればOK**。

| 道具 | 何に使う？ | 範囲 |
| --- | --- | --- |
| HTML（Blade） | 画面の骨組み | 範囲内 |
| Tailwind（CDN） | 見た目。`class="..."` だけで色や大きさを決める。**`<style>` やCSSファイルは書かない** | 範囲内 |
| JavaScript | ボタンを押した時の動き、数秒ごとの自動更新、文字を流す動き | 範囲内 |
| PHP / Laravel | ルーティング、コントローラー、バリデーション、マイグレーション、Eloquent（データベース） | 範囲内 |

### 範囲の外かもしれないもの（＝説明を用意しておくもの）
w07 の資料をもう一度見て、習っていたら「範囲内」に書き直してください。習っていなければ、下の「使った理由」をそのまま発表・提出資料に使えます。

| 使ったもの | 使った理由（説明文） |
| --- | --- |
| `fetch()` で JSON を受け取る | ページを読み込み直さずに、新しい投稿やリアクションの数だけを取りに行くため。講演中に画面がチカチカ再読み込みされると見づらいから。 |
| `setInterval()` で **2秒ごとに取りに行く**（ポーリング） | 他の人の投稿をほぼリアルタイムで見せるため。WebSocket などのリアルタイム通信は難しく10時間では作れないので、習った `fetch` を繰り返す一番かんたんな方法を選んだ。 |
| `element.animate()`（Web Animations API） | スクリーンで文字を右から左へ流すため。ルールで CSS（`@keyframes`）が書けないので、JavaScript だけで動きを作れるこの方法を選んだ。 |
| Laravel のセッションID | ログインなしで「この人はもう👍を押した」を見分けるため。匿名のまま、1人が何回も押せないようにした。 |
| Tailwind の `[ ]`（任意の値）例 `shadow-[4px_5px_10px_rgba(166,182,210,.6)]` | デザインの丸いボタンの影など、Tailwind に用意されていない値を CSS を書かずに指定するため。 |

> 💡 ほかにも「範囲外かな？」と思うものを使ったら、その場でこの表に1行足してください。最後に慌てなくてすみます。

## 3. しくみを小学生向けにたとえると

- **データベース** ＝ 学校の **黒板**。みんなの質問・感想・リアクションが全部書いてある。
- **Laravel（サーバー）** ＝ 黒板の前にいる **係の人**。「書いて！」と頼まれたら書き、「見せて！」と頼まれたら読み上げる。
- **画面（ブラウザ）** ＝ 教室にいる **みんな**。
- **2秒ごとの自動更新** ＝ みんなが2秒ごとに「黒板、なにか増えた？」と係の人に聞く。
- **Issue** ＝ **やることカード**。「何を・どこまでやったら終わりか」を書いたカード。
- **ブランチ** ＝ 自分専用の **ノートのコピー**。失敗しても本物のノート（main）は汚れない。
- **プルリクエスト（PR）** ＝ 「できたよ、見て！」と **先生（仲間）に丸つけを頼む** こと。
- **マージ** ＝ 丸がついたので、本物のノートに **書き写す** こと。

```
 参加者のスマホ ──「投稿したい！」──▶ Laravel ──書く──▶ データベース
 スクリーン    ──「2秒ごと: 新しいのある？」──▶ Laravel ──読む──▶ データベース
 講演者の画面  ──「この質問に答える！」──▶ Laravel ──「回答中」と書く──▶ データベース
```

## 6. 毎回の作業の流れ（Issue駆動のやり方）

**カード1枚 ＝ ブランチ1本 ＝ PR 1つ** が基本です。

### ① やることカード（Issue）を選ぶ
GitHub の Issues から自分のカードを開き、右の **Assignees** に自分を入れる（「わたしがやります」のしるし）。

### ② main を最新にして、自分用のノート（ブランチ）を作る
ブランチ名は `feature/Issue番号-かんたんな英語` にします。

```bash
git switch main
```
```bash
git pull origin main
```
```bash
git switch -c feature/7-post-api
```

### ③ 作業して、こまめにセーブ（コミット）する
コミットメッセージの最後に `#Issue番号` を入れると、GitHub の Issue にコミットが表示されます。

```bash
git add .
```
```bash
git commit -m "投稿を保存するAPIを追加 #7"
```

> 💡 30分に1回はコミット。動いたらすぐコミット。「動いていた時点」に戻れるようになります。

### ④ GitHub に送って、丸つけを頼む（push → PR）
```bash
git push -u origin feature/7-post-api
```
GitHub で **Compare & pull request** を押す → 本文のテンプレートを埋める → **`closes #7`** と書く → **Reviewers** に1人入れる。

### ⑤ 仲間がチェックする（レビュー）
- たのまれた人は **15分以内** に見る（待たせると全員が止まる）
- 「Files changed」を見て、手元でも動かしてみる → OK なら **Approve**
- 時間がないので、細かい好みの話はしない。**動かない・壊れる** ところだけ指摘

### ⑥ マージする → カードが自動で閉じる
**Merge pull request** を押す。`closes #7` のおかげで Issue #7 が自動で Closed になります 🎉

### ⑦ 全員、手元の main を最新にする
だれかがマージしたら、チャットで「#7 マージしたよ」と伝える。みんなは:
```bash
git switch main
```
```bash
git pull origin main
```
作業中のブランチに最新を取り込みたいときは、自分のブランチで:
```bash
git merge main
```

## 7. みんなで守るルール

1. **main に直接 push しない。** 必ずブランチ → PR → マージ。
2. **自分の担当ファイル以外はさわらない。** さわる必要があるときは、先にチャットで言う。
3. **CSS を書かない。** `<style>` タグも `.css` ファイルも使わない。見た目は全部 Tailwind の class で。
4. **投稿の文字は `textContent` で表示する。** `innerHTML` にそのまま入れると、`<script>` を投稿されたときに悪いプログラムが動いてしまう（XSS）。Blade では `{{ }}` を使う（`{!! !!}` は使わない）。
5. **こまったら15分ルール。** 15分考えてわからなければ、すぐ仲間に聞く。
6. **範囲外の技術を使ったら、すぐ「2. 使う道具」の表に1行足す。**
7. **`.env` は GitHub にあげない。**（Laravel では最初から `.gitignore` に入っています）

## 8. 設計図（データベース・URL・API）

**3人がこの設計図を「約束」として作ります。** 勝手に変えたくなったら、チャットで相談してからこの README を直してください。

### データベースの表

**posts**（質問と感想）

| 列 | 型 | 意味 |
| --- | --- | --- |
| id | 番号 | 自動 |
| type | 文字 | `question`（質問）か `comment`（感想） |
| body | 文字（120文字まで） | 内容 |
| status | 文字 | `open`（まだ）/ `answering`（いま回答中）/ `answered`（回答済み）。最初は `open` |
| created_at / updated_at | 日時 | 自動 |

**reactions**（だれが・どの投稿に・どの反応をしたか）

| 列 | 型 | 意味 |
| --- | --- | --- |
| id | 番号 | 自動 |
| post_id | 番号 | どの投稿か（posts.id） |
| kind | 文字 | 絵文字（`👀` `💡` `🙌` `🤔` `💯` `😂` `👏` `🔥`）か、`like`（私も聞きたい）か `heart`（共感） |
| visitor_id | 文字 | 押した人のしるし（セッションID）。名前は保存しない＝匿名 |
| created_at / updated_at | 日時 | 自動 |

- `post_id` + `kind` + `visitor_id` の組み合わせは **1つだけ**（ユニーク）。同じ人が同じ反応を2回できない。
- もう一度押したら **取り消し**（行を消す）。

### 画面の URL

| URL | 画面 | 担当 |
| --- | --- | --- |
| `GET /` | 参加者画面 | B |
| `GET /screen` | スクリーン画面 | C |
| `GET /speaker` | 講演者画面 | C |

### API（JavaScript から `fetch` で呼ぶURL）

`routes/web.php` に書きます（セッションとCSRFが使えるように）。
POST のときは、ヘッダーに **CSRFトークン** をつけます（下の「共通の fetch のしかた」参照）。

| メソッドとURL | 送るもの | 何が起きる？ |
| --- | --- | --- |
| `GET /api/state` | なし | 投稿全部と「いま回答中」の情報を返す（2秒ごとに呼ぶ） |
| `POST /api/posts` | `{ "type": "question", "body": "..." }` | 投稿を保存。空や121文字以上はエラー（422） |
| `POST /api/posts/{id}/reactions` | `{ "kind": "👀" }`（または `"like"` / `"heart"`） | 押してなければ追加、押してあれば取り消し |
| `POST /api/posts/{id}/answer` | なし | その質問を `answering` に。前に回答中だった質問は `answered` に |
| `POST /api/posts/{id}/done` | なし | その質問を `answered` に |

#### `GET /api/state` が返す JSON の形（これが一番大事な約束）

```json
{
  "current_id": 1,
  "posts": [
    {
      "id": 1,
      "type": "question",
      "body": "失敗した時、どうやって立ち直りましたか？",
      "status": "answering",
      "reactions": { "🤔": 3, "👀": 4 },
      "my_reactions": ["👀"],
      "like": 18,
      "heart": 7,
      "my_like": true,
      "my_heart": false,
      "created_at": "2026-11-20T10:00:00.000000Z"
    }
  ]
}
```

- `posts` は **古い順**（id の小さい順）。新しい順に見せたいときは JS 側で逆にする。
- `current_id` は「いま回答中」の質問の id。なければ `null`。
- `reactions` には絵文字だけを入れる（`like` / `heart` は別の項目）。
- スクリーンは「前回見た一番大きい id」より大きい投稿だけを **新しく流す**。

#### 共通の fetch のしかた（B・C 用のお手本）

Blade の `<head>` に（Aさんが layouts に入れておく）:
```html
<meta name="csrf-token" content="{{ csrf_token() }}">
```

JavaScript:
```js
const token = document.querySelector('meta[name="csrf-token"]').content;

// 読むとき
async function getState() {
  const res = await fetch('/api/state');
  return await res.json();
}

// 書くとき
async function post(url, data = {}) {
  const res = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'Accept': 'application/json', 'X-CSRF-TOKEN': token },
    body: JSON.stringify(data),
  });
  return res;
}

// 2秒ごとに最新を取りに行く
setInterval(async () => {
  const state = await getState();
  render(state); // 自分の画面を描き直す関数
}, 2000);
```

#### 文字を流すお手本（C 用 / CSS を書かずに動かす）

```js
function flow(post) {
  const el = document.createElement('div');
  el.textContent = post.body;                     // ← innerHTML は使わない
  el.className = 'absolute whitespace-nowrap text-2xl font-bold text-white';
  el.style.top = (70 + Math.floor(Math.random() * 5) * 52) + 'px';
  el.style.left = '100%';
  sky.appendChild(el);
  const distance = sky.clientWidth + el.clientWidth;
  const anim = el.animate(
    [{ transform: 'translateX(0)' }, { transform: `translateX(-${distance}px)` }],
    { duration: 9000, easing: 'linear' }
  );
  anim.onfinish = () => el.remove();
}
```

## 9. こまったときは

| こまったこと | まずやること |
| --- | --- |
| 画面が真っ白／500エラー | `storage/logs/laravel.log` の一番下を見る。ブラウザの開発者ツール（F12）の Console と Network も見る |
| POST すると 419 エラー | CSRF トークンが送れていない。`<meta name="csrf-token">` と `X-CSRF-TOKEN` ヘッダーを確認 |
| POST すると 422 エラー | バリデーションで弾かれている。送っている JSON の形を「8. 設計図」と見比べる |
| データベースのエラー | `php artisan migrate:fresh --seed` で作り直す（**データが全部消える**ので本番前だけ） |
| 他の人の変更が反映されない | `git switch main` → `git pull origin main` → 自分のブランチで `git merge main` |
| コンフリクトした | あわてずに、`<<<<<<<` から `>>>>>>>` の間を見て、両方の変更を残すように直す。わからなければ、その部分を書いた人と画面を見ながら直す |
| スマホから見られない | PCとスマホを同じWi-Fiにして、`php artisan serve --host=0.0.0.0` で起動し、スマホで `http://PCのIPアドレス:8000` を開く（授業の環境が Docker なら、その手順に合わせる） |
